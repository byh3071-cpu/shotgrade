# AI 도구 3종 운영 지침

Cursor, Claude CLI, Codex CLI를 동시에 쓰더라도 같은 파일과 같은 산출물을 동시에 수정하지 않기 위한 규칙이다. 코드, 설정, 문서 작업에 모두 적용한다.

## 1. 목적

- 같은 산출물에 대한 동시 수정을 막아 충돌과 되돌리기를 최소화한다.
- 도구별 작업 lane을 고정해서 책임 범위를 분리한다.
- 병렬 작업은 가능할 때만 허용하고, 결과 통합은 한 사람이 담당한다.
- 모든 CLI 작업은 종료 시 작업 로그를 남긴다.

## 2. 용어

| 용어 | 정의 |
| --- | --- |
| 산출물 | 수정 대상이 되는 파일, 브랜치, 디자인, 문서, 기능 단위 |
| 단일 작성자 규칙 | 하나의 산출물은 한 번에 하나의 도구만 수정한다는 규칙 |
| lane | 도구별로 허용된 작업 종류 |
| 드라이버 | 현재 작업을 끝까지 책임지는 주 작업 도구 |

## 3. 도구별 기본 역할

| 도구 | 담당 lane | 피해야 할 일 |
| --- | --- | --- |
| Cursor | 기능 구현, 리팩터링, UI 수정, 디버깅, 로컬 실행 | CLI가 이미 수정 중인 같은 파일 편집 |
| Claude CLI | 기획, 요약, 카피, 오류 로그 해석, 코드 없는 초안 | 같은 브랜치에서 소스 파일 직접 수정 |
| Codex CLI | 작은 패치, 진단, 문서 정리, 자동화 보강, 검증 | Cursor가 편집 중인 같은 파일 동시 수정 |

역할을 바꿀 때는 세션 시작 시에만 바꾼다. 작업 중간에는 한 산출물의 드라이버를 바꾸지 않는다.

### ShotGrade 정의서 정렬 (프로젝트별)

| 도구 | 정의서상 우선 담당 |
| --- | --- |
| Cursor | UI·페이지·`app/api/analyze`·Supabase 연동 |
| Claude CLI | `lib/prompts.ts`, DB 스키마·타입 검토, Vision 프롬프트 튜닝 |
| Codex CLI | 테스트·보일러플레이트·린트·반복 패턴 정리 |

**권장 순서:** Claude CLI로 설계·프롬프트 정리 → Cursor로 구현 → Codex로 테스트·정리 → 커밋.

## 4. 충돌 방지 규칙

1. 같은 파일은 동시에 한 도구만 수정한다.
2. 하나의 기능 또는 버그는 한 도구가 끝까지 맡는다.
3. 다른 도구가 만든 변경은 되돌리지 않는다. 필요한 경우 그 변경 위에 맞춰 작업한다.
4. `rm`, `git reset --hard`, 강제 push 같은 위험 명령은 사용자 승인 후 실행한다.
5. 코드 작업 전에는 `AGENTS.md`를 먼저 확인한다.
6. CLI는 종료 시 `docs/codex-work-log.md` 또는 해당 도구의 로그 문서에 기록한다.

## 5. 병렬 작업 허용 매트릭스

| 조합 | 허용 조건 |
| --- | --- |
| Cursor + Claude CLI | Claude는 문서, 기획, 카피만 다루고 소스 파일을 건드리지 않는다. |
| Cursor + Codex CLI | 서로 다른 파일을 수정하거나 Codex는 진단과 문서 작업만 수행한다. |
| Claude CLI + Codex CLI | 둘 다 코드 직접 수정 없이 설명, 분석, 문서 초안만 작성한다. |

금지되는 조합:

- Cursor와 Codex가 같은 파일을 동시에 수정한다.
- 여러 도구가 같은 기능을 중복 구현한다.
- 한 도구가 다른 도구의 미완료 변경을 임의로 정리하거나 되돌린다.

## 6. Git 병렬화 규칙

여러 갈래로 동시에 진행해야 하면 브랜치를 분리한다.

| 패턴 | 설명 |
| --- | --- |
| `feat/<name>-cursor` | Cursor 전용 구현 브랜치 |
| `research/claude-<topic>` | Claude 전용 조사, 문서 브랜치 |
| `exp/codex-<topic>` | Codex 전용 실험 패치 브랜치 |

병합은 사용자 또는 현재 드라이버가 담당한다. 충돌 해결은 한 세션에서 끝낸다.

## 7. 세션 시작 체크리스트

- 이번 작업의 드라이버 도구를 하나 정한다.
- 다른 도구가 같은 파일을 만지고 있는지 확인한다.
- 작업 전 `git status --short`로 변경 상태를 확인한다.
- 코드 작업이면 `AGENTS.md`와 관련 Next.js 문서를 확인한다.
- 작업 범위를 벗어난 변경은 건드리지 않는다.

## 8. Codex 작업 규칙

Codex는 기본적으로 다음 범위만 맡는다.

- 현재 요청을 처리하는 데 필요한 최소 파일 수정
- 문서 정리, 로그 작성, 작은 설정 보강
- 테스트, 린트, 빌드 같은 검증
- 충돌 위험이 있는 기능 코드 대신 제안 또는 별도 문서화

Codex가 작업을 끝내면 반드시 `docs/codex-work-log.md`에 시간, 작업 범위, 수정 파일, 검증 결과, 남은 리스크를 기록한다.

## 9. 요약

구현은 가급적 Cursor가 맡고, CLI 도구는 문서화, 진단, 작은 패치, 검증에 집중한다. 같은 파일과 같은 기능을 동시에 여러 도구가 수정하지 않으며, 작업이 끝나면 로그로 현재 상태를 남긴다.
