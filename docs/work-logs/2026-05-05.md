## 12:08 — CorrectionDrawer pre-fill 최종 수정 (81a4936)

- **레인:** Claude CLI (컴포넌트 리팩터)
- **변경 파일:** `components/correction-drawer.tsx`
- **문제:** 서브에이전트 1차 구현은 `onOpenChange` 래핑으로 폼 리셋했는데, vaul이 `onOpenChange`를 내부 이벤트(드래그/Esc)에서만 호출하고 부모가 `open` prop을 false→true로 뒤집을 땐 호출하지 않아서 pre-fill이 안 됐음. 2차 시도(11:41 `ddfdcd3`)는 render-time setState 패턴(`prevOpen` 추적)을 썼지만 vaul Drawer의 open/close 사이클 전반에서 안정적으로 발화하지 않음 — wrapper가 계속 마운트돼 있어서 `useState` initializer가 최초 1회만 실행.
- **최종 해결:** `CorrectionForm`을 inner 컴포넌트로 분리하고 wrapper가 `{open ? ... : null}`로 조건 렌더 → 매 오픈마다 폼이 새로 마운트되며 `useState` initializer가 현재 `initialCorrection` prop으로 재실행. React가 권장하는 "prop 변경 시 state 리셋" 패턴(useEffect 없이).
- **재현 시나리오:** B 보정 제출 → drawer 닫힘 → 👎 재클릭 → drawer 재오픈. 수정 전: 등급 강조 없음. 수정 후: B 강조 + 노트 pre-fill. 사용자 재테스트 확인 대기 중.
